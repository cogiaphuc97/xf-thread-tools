# CLAUDE.md

## What this is

Tampermonkey userscript for XenForo 2 forums: reaction-sorted thread view + a media/links/AI drawer panel with album expansion and bulk zip download. Source lives in `src/` (pure ESM modules + order-preserving runtime fragments, mapped in `scripts/modules.json` and `docs/MODULES.md`); the single-file deliverable `xf-thread-tools.user.js` is BUILD OUTPUT — never edit it, edit src and run `npm run build`. `package.json` is dev scaffolding. Repo `cogiaphuc97/xf-thread-tools` (public, `main`), auto-update via `https://raw.githubusercontent.com/cogiaphuc97/xf-thread-tools/main/xf-thread-tools.user.js`. Site-specific facts (domains, NSFW conduct rules, probe evidence) live in gitignored `.claude.local.md` — never commit hostnames; code stays shape-based.

## Commands

```bash
npm run build                          # assemble src/ -> xf-thread-tools.user.js (zero-dep, node --check gated)
npm test                               # unit tests (node:test): one file per src module + smoke on the bundle
node --check xf-thread-tools.user.js   # syntax gate (build already runs it)
node tests/live-headless.mjs           # live probe vs a real thread page (Chrome + network; NOT in npm test)
```

Probe harness: `/opt/google/chrome/chrome --headless=new` over raw CDP WebSocket (node stdlib, zero deps), injects `/tmp/xf-serve/inject.js`. **Rebuild after every src edit or probes test stale code:** `npm run build && cat /tmp/xf-serve/stub.js xf-thread-tools.user.js > /tmp/xf-serve/inject.js` (`stub.js` = GM shims on localStorage, prefix `xft_`).

- Every change request bumps `@version` in `src/shell/meta.js` AND `package.json` in sync (build stamps it into the bundle), then commit + push. State the version in the reply.
- raw.githubusercontent serves stale versions for minutes after push — verify via `https://api.github.com/repos/cogiaphuc97/xf-thread-tools/commits/main`.

## Architecture

`src/` splits by function (see `docs/MODULES.md` for the full graph + rules):

- **Pure modules** (`src/config|parse|media|embed|zip|dlplan|layout|ai.mjs`): real ESM, importable, unit-tested per module (`tests/<module>.test.mjs`). No DOM, no GM_*. May import each other (no cycles; build topo-sorts).
- **Runtime fragments** (`src/rt-*.js`): order-preserving byte-slices of the original `main()` body — plain scripts sharing main()'s scope, NO imports. Manifest order = bundle order.
- **Shell** (`src/shell/`): `meta.js` (userscript header, version), `guard.js` (runtime guard), `umd-tail.js` (node export tail).
- **Build** (`scripts/build.mjs`): strips import/export from pure modules, concatenates shell + pure (topo) + `function main() { fragments }` + tail into `xf-thread-tools.user.js`; runs `node --check` before writing; silent on success (ralph verify fingerprints stdout).
- One IIFE behind the runtime guard: DOM/GM code runs only on `<html id="XF" data-template="thread_view">`; under Node the guard keeps the bundle inert (tests import pure modules directly; smoke still requires the bundle).
- **Extraction**: `extractPost(art)` collects media/links from `.bbWrapper` + whole-article attachment scan (XF renders attachment blocks outside the body). Skips `blockquote.bbCodeBlock--quote` content (quotes are copies of other posts) and `.message-signature`.
- **Cache**: IndexedDB `xf-thread-tools`, stores `posts` (records with bodyHtml) + `threads` (meta incl. `pagesDone[]` resume set). `ensure(force)` = panel path (partial data usable, never auto-refetch); `ensureForSort()` = sorter path (resumes missing pages). 100 MB persistence cap, in-memory fallback.
- **Media grid is virtualized** (0.8.0): exact-height spacer + pooled rows; see Grid gotchas.
- **Preview thumb cache** (0.20.0): pure `src/thumb.mjs` + runtime `src/rt-thumbcache.js` — cells fetch a preview ONCE (GM blob fetch, referer ladder, imgPageNet-queued), downscale to ≤512px webp stills, persist in IDB stores `thumbs`/`thumbsMeta` (DB v2, 512MB LRU) behind a 128MB memory objectURL layer; gifs split into still thumb + original-bytes LRU (hover/viewer play). See Grid gotchas.
- **Selector overrides**: `BASE_SEL` merged with `settings.selectors` (GM key `xfThreadTools:settings`); every selector user-overridable.
- **AI tab**: OpenAI chat-completions wire shape; Ollama-only phase (native `/api/chat`, `think:false`). API key in GM storage only.

## Gotchas — extraction & data

- Extraction fixes don't retro-fix old data: per-thread IndexedDB records persist across versions. After shipping an extraction fix, tell the user to hit **↻ Refresh** on affected threads.
- Quote selector is `blockquote.bbCodeBlock--quote`; `.bbCodeBlock.quote` matches nothing.
- `img.bbCodeBlockUnfurl-image` (link-preview cards) deliberately NOT collected — brand logos/placeholders. Do not re-add.
- Smilies (class `smilie*` / URL `/smilies/`) and boilerplate (same URL in ≥3 distinct authors = "via app" footer) are double-gated: skipped at extraction AND filtered at render. Footer links have no structural marker — only the fingerprint catches them.
- Lazy-image XF themes: `<img src="data:..." data-src="REAL">` — extraction must prefer data-src/data-url when src is data:/blob:. A 1×1 placeholder loads "successfully" (nw=1, complete, no error) — probe for complete+nw≤1.
- Embed iframes: third-party video hosts embed `<iframe src=…/embed/ID>`; the inner `<video>` src is signed+expiring — collect only the iframe URL (record field `embeds`; OLD RECORDS LACK IT — render must guard undefined).
- Landing-page image HQ (0.7.48): re-encoded embeds (`/th/` dir, random uuid) have their original only on the image's landing page (`/img/<short-id>`). `extractPost` captures the wrapper anchor into per-record `imgPages` (old records lack it — Refresh to gain). `imagePageHref` validates the shape `/img/[A-Za-z0-9_-]{3,64}`; `parseImagePage` extracts carriers in trust order meta-refresh > og:image/twitter:image > `<img src>` > `<a href>`, keeping query strings verbatim (signatures). Two resolve routes: `<origin>/api/images/<id>` JSON (`image.original_url`, not challenge-gated) → page HTML fallback. Applied in THREE places: grid cells (embedded copy renders, original swaps in seamlessly AFTER `setStage(ci)` — a sync cache hit fires its swap immediately and setStage's src write would overwrite it), the viewer, and `buildDlJobs` (zip entry name keeps the embedded basename, bytes from the full URL). NOT applied when a static `.md`/`.th` marker chain exists (cheaper, proven).
- HQ marker chain (0.7.35+): post-body images with `.md`/`.th` before the extension are medium variants — two shapes: marker-only `<uuid>.md.jpg` (full size = path minus `.md`) and dims-prefixed `<WxH>_<name>.md.jpg`. `hqCandidates()` = [drop marker+dims → drop marker keep dims → post URL]; `buildMediaEl` walks it on load errors, stage remembered per session. No marker, no chain — shape-based, no hostnames.

## Gotchas — grid, rows, render

- Sort button must never be disabled while its fetch is pending — second click is the cancel affordance.
- Video cells append `#t=0.1` for poster-frame seek — normalize the hash when comparing URLs in tests.
- Video/embed grid cells are styled tiles — resolution fires only in the viewer or download runner; assert against fixture-server hits, not grid DOM.
- Panel render has a signature dedupe (`sig === lastPanelSignature` early-return) — anything that must update on state transitions (partial-fetch note, Resume visibility) must be part of `noteSig` or it silently stays stale. CRITICAL: `clearVRows()` resets `lastPanelSignature` — cleared rows + unchanged sig made renderPanelBody early-return and leave the grid EMPTY forever.
- Always use `clearVRows()` (detach + clear), never `vrowCache.clear()` alone — the latter leaves orphan row elements in the DOM (the short/blank mid-grid rows bug).
- Row identity: every layout entry gets a signature stored in `dataset.xftSig`; cached rows whose sig mismatches rebuild. Pool row keys are FULL URL membership (`r:url1|url2|…`) — first-url+length keys rode retired cells along. `collectMediaItems` stamps `ord` = position in the RAW unfiltered stream (retirement must not renumber); rows bucket by `floor(ord/4)`; `reconcileRowCells` re-homes surviving cells BY URL so img elements move between rows without refetching. Cell clicks resolve index at CLICK time via `viewerItems.findIndex` (fill-time closures go stale).
- Virtualizer preconditions (do not break): (1) heights exact — `.xft-cell{aspect-ratio:1}`, headers CSS-fixed; `layoutMetrics` computes the spacer, never estimate. (2) window membership derived SYNCHRONOUSLY from scrollTop (`windowRange` binary search) + synchronously after programmatic scrolls — no IntersectionObserver on the correctness path. (3) rows recycle by content sig. `mountVirtualGrid` probes one real row + both header kinds per mount and MUST force the body scrollbar first (`vrows.style.height = clientHeight+1`) — a fresh spacer drops the scrollbar, the probe row measures wide, drift compounds (~2.5px/row). `renderSlice` does incremental DOM sync (insertBefore/appendChild only; zero-op guard). `renderPanelBody` stashes the attached window into the pool BEFORE `replaceChildren`, mounts AFTER. Pool `VPOOL_MAX` 120 rows LRU, overscan 900/1400px. Row cache + observer hold STRONG refs — unobserve detached rows.
- Dense packing: rows pack sequentially (ceil(items/4)) — no holes after retirements; re-chunking is safe because reconcile re-homes by URL. Whole-row DISCARD on retirement is the cascade bug (0.7.47) — never bring it back.
- **Thumb-cache cells (0.20.0)**: cell imgs render from `blob:` objectURLs — identity checks use `cell.dataset.xftUrl`, NEVER `img.src`. `thumbFor(url, cb)` returns the URL synchronously on a memory hit (cb fires async otherwise, exactly once). `thumbFetch` takes an ARRAY of callbacks — passing a bare fn breaks the `for..of` settle and freezes the net queue. Animated detection: `isGifUrl(url) || blob.type==='image/gif'`; animated sources ALWAYS re-encode the still (small gifs too). ↻ Refresh clears `thumbNeg` with the other failure state but KEEPS bytes. Viewer/downloads bypass the cache (full-res); the in-cell landing-page HQ swap is GONE (cells never pull originals).
- **Scroll-idle gate (0.20.0)**: `deferGridRebuild()` (rt-grid) holds grid rebuilds while `scrollIdleHeld(lastUserScrollAt, now, 150)`; used by notify, albumDone, albumPrimeRender, scheduleBrokenRerender (the old 80ms hold folded in). `scheduleCountsOnly()` keeps counts/subtab numbers live during holds. `setTab`/`setSubTab` bypass the gate (user clicks render immediately). The wheel listener on the panel body feeds `lastUserScrollAt` directly — mount scroll-restores refresh `programmaticScrollAt` and its 40ms guard would misread wheel scrolls as programmatic (gate flap bug, fixed).
- **Probe-height cache (0.20.0)**: `mountVirtualGrid` skips the forced-reflow probe when `probeHeightsValid(vProbeCache, vProbeGen)`; the resize observer bumps `vProbeGen` (≥2px body width change). Heights are CSS-fixed — do not add per-mount re-probes back.
- Loading gate: pending cells carry `.xft-loading` (skeleton + shimmer, sweep alpha ≥ .20); images `opacity:0 + blur(6px)` until `.xft-ok` then .35s reveal — progressive JPEGs otherwise paint part-by-part and read as broken. Never placeholder-then-hide: failed media retire via brokenMediaUrls + 300ms-debounced BATCHED re-render.
- Motion rules: `.xft-out` declared AFTER `.xft-loading` (loading+dying cell must fade, not shimmer). Rebuilt rows carry `.xft-nopop` 450ms (`popSuppressUntil`). Viewer pops only on fresh opens. User's OS runs prefers-reduced-motion — reduce rules scoped `html:not(.xft-anim-force)`, `forceAnimations` setting toggles the class at boot + save.
- EVERY `display:flex` strip needs its own `[hidden]{display:none}` rule — flex beats the UA `display:none` and the bar renders empty. Hit repeatedly (dlbar, jumps). Probe computed visibility, never the attribute.
- Scroll memory: every view (tab × sub-tab × group, `viewKey()`) keeps its own offset; `saveViewScroll()` before every switch; build new body OFF to the side (never `textContent=''` — collapses height, clamps scrollTop); restore = one direct `scrollTop` set; removal rebuilds anchor on first visible ROW's sig.
- Panel fetch UX: while `hub.fetchRunning`, progress shows `⟳ n/N`, Stop/Refresh DISABLED (user request; sort button keeps click-to-cancel). Media/links render strictly page 1 → last (frontier = contiguous `pagesDone`); idle shows all cached partial data.
- Media grouping: `Group` select — flat | post | page | user, persisted `settings.mediaGroup`; renderer walks `buildMediaLayout()` entries (headers + ≤4-cell rows), not raw rows.

## Gotchas — networking

- Net pools (0.22): imgPageNet (thumbs + landing pages) = per-origin cap 4 + global 12 + 60ms start gap, VISIBLE-FIRST pick (pure `netPick` in `src/imgnet.mjs`), plus ADAPTIVE per-origin penalty (0.22.3): a failed fetch (challenge page / block pixel / dead referer ladder, signalled from `thumbNeg` adds + `imgPageGet` errors via `imgNetPunish`) drops that origin to 2-concurrent + 350ms start spacing for 60s×trips (max 5min) — some CDN families (the scdn poster infra) challenge cookie-less bursts above 2 and 403 the whole session; healthy origins keep the fast profile. Urgency: no-el jobs (landing pages/viewer/downloads) always urgent, element jobs urgent iff connected + rect within viewport ±300px, 10s aging bound; urgency re-evaluated per pump, enqueue defers the pump one macrotask (cells enqueue before row attach — a sync pump reads them all as off-screen). localhost hook `window.__XFT_IMGNET_FOR_TESTS = {global, perOrigin, gap, penalize:[origins]}` read per pump. Poster net unchanged (2/350, backoff — the 403 lesson lives there). HQ chain: 3/250ms. Downloads: files 6 global / 4 per origin, connections 12/8; GM XHR 2-at-a-time/400ms gap in the zip runner.
- File-host adapters are three distinct routes inside `resolveEmbedStream`: GET sign endpoint (`/embed/<id>` → `/api/sign`), POSTed token endpoint (`/d/<slug>` → `/v2/api/public/view`, needs `gmPostJson` — a JSON POST fires a CORS preflight on the fetch fallback that real GM_xmlhttpRequest never sends), HTML page parse (`/v/`, `/f/` → carrier regexes). `/f/` pages carry `var jsCDN   = "https:\/\/…"` — THREE spaces before `=` and escaped slashes; regexes must not assume single spacing.
- Native video playback for embeds with a working `<origin>/api/sign?v=<ID>` endpoint: `<video controls referrerpolicy="no-referrer">` (CDNs 403 foreign referers, serve no-referer); signed URL cached until 60s before exp; any failure falls back to the embed iframe — do NOT add a sandbox attr (players need scripts).
- Referer rules (0.18.2): CDN families split unknowably per URL — some enforce the forum referer (403 no-referer, hotlink block pixel otherwise), some 403 foreign referers and serve no-referer. Rule: page-default policy FIRST (panel page IS the forum), ONE no-referrer retry, then give up. The retry must CACHE-BUST (`?xftref=1`) — the image cache is URL-keyed, a policy change alone replays the poisoned entry. `loadSwapImg` installs the URL that loaded and copies the working policy onto the cell img. A load of a ≤1px image is FAILURE (block pixels are valid 1×1 PNGs). `{once:true}` on load listeners is wrong for retry loops — the block-pixel load consumes the listener. Videos/embed streams keep `referrerPolicy='no-referrer'` (verified 206s).
- Downloads set `Referer: <forum origin>/` on GM fetches for cross-host media (GM may set the header; fetch may NOT — the fetch fallback passes the spec-legal `referrer` init option). Same-host gets none.
- HQ resolve failures cool down, never cache: only SUCCESSES write `imgPageCache`; failures set `imgPageCooldown` 30s (capped 400). Grid cells respect the cooldown; viewer + download jobs pass `force`. Each cell arms ONE delayed forced retry (31s). `gmGetText`'s fetch fallback has a 10s AbortController leash (a hung fetch starves the queue). Same pattern for album fetch failures (60s cooldown, never cached empty).
- Page fetch retries: each thread page retries ≤2× (3s → 8s backoff, 15s fetch leash) before declaring partial; 404/410 immediately fatal; Stop/abort wins instantly.
- Failure policy (0.8.1): isolated failure on a healthy origin = dead file → fast path (skip HQ retry, retire fast, debounced rerender 180ms). Bursting origin (per-origin rolling history: last 24, verdict on last 8, ≥3 samples, ≥50% fail) → items HOLD slots: `.xft-stalled`, src stripped, `checkDead` skips stalled urls. Background recheck ladder 4s/15s/40s; success → `recoverInPlace` rebuilds only that item's cells; exhausted → retire. `STALL_PER_ORIGIN_MAX` 12. Ramp cost: first 2–3 burst failures die fast-fail. Refresh clears stalls.
- Sticker gate: both-axis naturalWidth/Height ≤ **140** retires at render (a real 180px image was retired at 200 once); mid-list removal must `clearVRows()` or the virtualizer serves stale rows.
- Stalled video: a 404 that never errors (networkState=LOADING forever) gets a 6s readyState check before retiring.
- `checkDead`/complete fast-path must skip src-LESS imgs (queued or mid-retry): `complete && nw<=1` on a src-less img retired whole ranges of healthy cells. Guard with `im.getAttribute('src')`.
- Session poison: broken marks, HQ stage, burned retries, tiny marks persist for the session — ↻ Refresh clears all four + `clearVRows()` before refetching (Refresh == mini-reload for failure state).

## Gotchas — downloads & zip

- Zip writer is STORE-method, hand-rolled, no deps (`zipStoreU8` + header builders, pure section). Never swap for a CDN script — single-file deliverable. Per-PART cap ~1 GB (32-bit zip offsets); a single file > `0xFFFFFFF0` bytes fails with a reason (u32le sizes would wrap silently).
- Split-zip (0.21.0): blobs land into `dlPartJobs`/`dlPartBytes`; at `dlPartCap()` (localhost test hook `__XFT_DL_PART_CAP_FOR_TESTS`, read PER-CALL so probes can change it between runs) the part seals → `dlSealQ` → `dlSealDrain` (ONE buildZipBlob at a time) → `dlSaveBlobAs` anchor save → `j.blob = null` free. Seals capture `dlRunSeq`; a stop/restart mid-build drops the stale `.then` entirely. Stop also drops QUEUED seals (parts already on disk stay). `dlFinish` takes the legacy single-zip path whenever nothing sealed early — under-cap runs keep the exact 0.20.0 filename; the only lone `.part1.zip` case is a run whose LAST byte crossed the cap exactly. The 'done'-phase dashboard writes a plain textContent summary that KILLS the stats spans — the 'fetch' phase strips that leftover text node first or the next run's stats glue together.
- Album downloads (0.21.0): `dlBegin(jobs, opts)` shared engine; `entryPlan:'albums'` switches entry naming to per-job `j.dir` (album folder + Pics/Videos via `dirOf`) and zip naming to `zipBase` (per-album button) or thread name (Album-tab main); legacy runs pass `null` and are byte-identical to 0.20.0. Outer album names via `safeOuterName` (Unicode kept, `:` → `_`); entry dirs via `sanitizeFileSeg`.
- Outer zip FILE name = `[Site] Title.zip` via `zipFileName(siteTagFromHost, cleanThreadTitle)` — site tag derived from `location.hostname` at runtime (drop `www.` + final TLD, titlecase; generic, no hostnames committed). Title = `h1.p-title-value` cloned with `a,[class*="label"],[class*="prefix"]` stripped, leading `[tag]` groups + trailing `" | Forum"` removed. Outer name KEEPS Unicode + spaces; only Windows-illegal chars die. Zip ENTRY names use ASCII-only `sanitizeFileSeg` — different jobs, different rules.
- Embed tiles are download jobs (`kind:'embed'`, forced `.mp4` name) — `dlTry` runs them through `resolveEmbedStream` first (shares the net slot). Unresolvable = FAILED (visible in dashboard), never skipped — All count and job total always match. `kind:'album'` tiles are skipped (navigation, not bytes).
- Images walk `hqCandidates` in jobs so never-rendered cells still land full-size (job NAME keeps cands[0]'s basename even when a later candidate supplied bytes); video `#t` hashes stripped.
- Download dashboard lives in the panel chrome BELOW the sub-tab row, NOT inside panelBody (re-renders must not wipe it). Rows: name `flex:1;min-width:0;ellipsis` + fixed bar/%/meta cluster — long filenames never shift layout. Jobs in flight + last 4 failed, reconciled in place.
- Chunked transfer (0.9.0): `Range` is CORS-unsafe on fetch → GM-path ONLY. Probe `bytes=0-(16MB-1)`: 206 + Content-Range total ≥ DL_CHUNK_MIN → parallel parts (probe body IS part 0); 200 → whole file; 206 without Content-Range → never save blind, noChunk single-stream retry. Part byte length MUST equal the requested span — mismatch = challenge page mid-run → discard ALL parts, noChunk retry (assembling would corrupt the zip).
- Retries: transient (network, 408/429, 5xx) same URL ≤2 (2s→6s, Retry-After capped 30s); other 4xx burns the URL → next candidate. Leashes: 30s TTFB, 45s mid-stream no-bytes, 180s read ceiling, 90s first-byte on dlFetch, 480s per-job watchdog. `dlRunSeq` run-identity guards stale watchdog timers across stop/start.
- Net-slot leaks freeze downloads (0.8.3): GM_xmlhttpRequest THROWS synchronously on unparseable URLs — wrap the call (try/catch → fetch fallback) or settle/release never runs and slots leak. Per-job ctx with idempotent release + killed flag; a parked part-starter must re-check ctx dead/released when a slot opens.
- Single-kind zips: `zipKindTag` from what DOWNLOADED (not the list) — images only → root entries + "(Images)"; videos only → "(Videos)"; mixed → Pics/ + Videos/.
- `panelData()` + `collectMediaItems()` are shared by grid and download — the zip list matches the grid exactly (boilerplate/smilies/broken filters included).

## Gotchas — AI tab

- Wire shape: OpenAI chat-completions (`{base}/chat/completions`, `{base}/models`) for everything; `aiEndpoint` accepts both `{provider,base}` and `{aiProvider,aiBase}`. Ollama preset base `http://localhost:11434/v1` for models; CHAT for ollama posts to the NATIVE `aiNativeChatUrl(base)` (strip `/v1`, append `/api/chat`) with `{stream:true, think:false}` — `think:false` exists only on the native wire; the compat layer silently drops it. Native streaming is NDJSON (`{"message":{"content"}}` + `{"done":true}`), not SSE — `aiSseParser(mode)` handles both, ignores `message.thinking`.
- All AI calls GM_xmlhttpRequest (CORS-free) with fetch fallback; 120s timeout, no stall leash (local models are slow to first token).
- Transcript rebuilt from the post cache EVERY SEND (`htmlToText` → `buildAiTranscript`): `[#pos] author (pN, ♥R)` lines, 700c/post + 24kc total, head(60%)+tail(40%). Query-boosted selection: `aiQueryTerms` + `aiScorePost` put top-40 relevant posts + top-reacted guarantees before the fill. SEARCH protocol: when the excerpt is truncated and the answer may be omitted, the model replies only `SEARCH: <keywords>`; the handler runs `aiSearchPosts` over the full cache, pushes a `note` bubble, re-asks with hits fenced; one follow-up max per send. Keywords feed the local lexical scorer only.
- AI view is REBUILD-GUARDED (`aiSeq` version counter) — fetch-progress ticks call renderPanelBody repeatedly; without the guard every tick wipes the input draft. Rebuilds stash+restore the draft (and pending state). The rebuild key uses provider/base/model ONLY.
- API key: GM storage only, NEVER localStorage (`readAiKey`/`writeAiKey` GM-only; `saveSettings` strips aiKey), NEVER in the DOM. Prompt-injection fence: transcript rides in its OWN user message between `<<<THREAD id=NONCE>>>` fences (per-request nonce); system prompt declares content untrusted; post text has `[#` rewritten to `[ #`.
- Any control whose value feeds a rebuild-triggering action must commit ON CHANGE, never wait for a Save (the 0.10.2 bug: config controls reverted to stored settings on every rebuild and calls hit real api.openai.com).
- Assistant bubbles render markdown via pure `mdParse`/`mdInlineTokens` → `mdRenderInto` with createElement/textContent ONLY — model output never touches innerHTML. Link hrefs locked to http(s) at the token level; no underscore emphasis (snake_case); soft newlines → `<br>`. User bubbles + errors stay literal.
- Streaming (0.11.x): `responseType:'stream'` + read via getReader/TextDecoder from `onloadstart` — TM MV3 fires only ONE progress event per GM_xmlhttpRequest, so onprogress-delta parsing pops whole replies in real Tampermonkey. `streamLive` flag ignores the redundant onprogress once the reader is live. Managers without stream support fall back to onprogress/one-shot. Pending bubble re-renders partial markdown every 150ms with ▍ cursor; Stop keeps the partial.
- `settings.aiLang` en|vi swaps the whole default prompt set; unknown falls back to en. Chat history is session-only in-memory.

## Gotchas — probes & CDP

- Always use a FRESH Chrome `--user-data-dir` per probe run — reuse keeps IndexedDB between runs and cached-partial threads take a different boot path. Reload the page BETWEEN injects — two injections on one page build duplicate panels and the stale one wins every `getElementById`.
- Probe order: nav → fake `html#XF[data-template]` attrs → settings → inject#1 → RELOAD → re-fake attrs → seed IDB → inject#2.
- Assert cells by dataset scan, not innerHTML counts (pooled/virtualized rows). Fixture slugs/ids must respect the real 3–64 length shapes the regexes enforce — 2-char ids fail `{3,64}` silently and look like parser bugs. GM stub needs `response: new Blob([t])` or download jobs die "HTTP 200 ✗".
- Burst/HQ probes run on a CSP-free page with faked XF attrs + a `/threads/<id>` path (page-CSP blocks cross-origin fetch); fake hosts need ACAO headers.
- `tests/fixture-server.mjs` + `tests/perf-headless.mjs` (0.20.0): zero-dep local fixture (thread pages, 200×150 PNGs via zlib — must stay >140px or the sticker gate retires them, 4000×3000 BMP, embedded animated gif, CROSS-HOST album server with ACAO — album classification is cross-host-only and the parser anchors RELATIVE `/f/` hrefs). Probe stub GM fetches are plain fetch: cross-host responses need ACAO or every thumb goes negative → native fallback. imgPageNet gap is 10ms on localhost (fixture politeness). Counters reset AFTER a reload's native page-`<img>` loads or they pollute refetch asserts. `tests/live-headless.mjs` asserts grid identity via `dataset.xftUrl` (blob cells).
- CDP `Fetch` drops Sec-Fetch-* headers — classify by Range shape (`bytes=N-M` full = downloader, `bytes=0-` open = `<video>` → park) + `Accept: image/*`. Fixture bodies must be decodable as grid previews, or click Download in the SAME synchronous eval as panel open (jobs lock before async grid errors mark items broken). `continueRequest` url-rewrite to local http from https pages = blocked — emulate dead streams by PARKING requests (leash fires). Never export a 100MB+ zip as base64 through `Runtime.evaluate` (CDP hangs) — verify the zip IN PAGE (EOCD parse) and return small JSON.
- Waiting for "an assistant bubble" must count a BASELINE first — the previous reply's bubble satisfies any `done>=1` poll.
- WSL→Windows Ollama: `localhost:11434` flaky under mirrored networking, default-gateway IP stable; Ollama's default CORS is `*`. Public https → localhost is blocked by Local Network Access — serve probe pages from 127.0.0.1.
